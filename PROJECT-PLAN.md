# Project plan: Morrow

## Brief

**Type:** Website design

**Problem:** Small teams often meet a complicated project tool before they understand what it helps them do.

**Audience:** A studio lead evaluating a lightweight team workspace.

## Experience flow

1. Arrive at a direct, descriptive introduction.
2. Review the sample interface and its scope before interacting.
3. Try the core control: Adjust the team size to explore a sample pricing state.
4. See a local result or demonstration state without sending a request to a service.

## Interaction

A team-size slider updates a clearly marked sample plan estimate; the primary action opens a local demo message.

## Key design decision

Lead with one human outcome, then show a compact product preview and let the visitor explore pricing without a signup wall.

## Boundaries

Fictional product and pricing. No subscription, account or checkout exists.

All named businesses, people, products, schedules, prices and quantitative values are fictional portfolio content. Replace them only with verified, permissioned material.

## Next iteration

Add a product-tour state and test copy hierarchy with a few target users.

## Learning goals

- Structure a complete page with meaningful headings, landmarks and labelled controls.
- Separate visual rules in CSS from interaction logic in JavaScript.
- Make states understandable with keyboard controls and live status text.
- Document assumptions and the boundary between a helpful prototype and a production service.
